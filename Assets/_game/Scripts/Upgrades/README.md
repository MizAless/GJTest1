# Экран улучшений

`BandolierUpgradeScreen` создаёт интерфейс; `UpgradeSelection` хранит выбор предложения/гнезда и запрос подтверждения. `UpgradePresentation` рендерит существующую анимацию патронташа и предметы в RenderTexture отдельной камеры (слой 30, сцена презентации расположена далеко от арены). Ресурсы загружаются из `Resources/Upgrades/PresentationAssets.asset`.

- Экран открывается между волнами. Первая стадия — патрон из трёх, вторая — модуль из трёх.
- Патронташ справа занимает 58% ширины. Выбор предложения запускает движение поверхности/царапин и небольшое покачивание модели.
- Без выбранного предложения нажатие на гнездо приподнимает патрон; второе гнездо меняет патроны местами. Модули остаются на местах.
- Предложение и гнездо можно выбирать в любом порядке. До подтверждения барабан не меняется; отмена/Esc сбрасывают выбор.
- После патрона экран остаётся открытым для модуля и перестановки. После подтверждения модуля доступны перестановка, крафт и покупки. Явная кнопка «Следующая волна» закрывает экран и возобновляет бой.
- Гнездо показывает отдельные подсказки патрона и модуля через StackedUpgradeTooltip. Предложения используют обычный TooltipTrigger.

`UpgradeAssetsAuthoring.BuildAssets` экспортирует презентацию из BandolierPreview, создаёт библиотеку, материал/меш скобы и начальную подгонку ранее не использовавшихся наконечников. Ручная сцена и шесть уже подогнанных спрайтов сохраняются. Повторная сборка перезаписывает генерируемые resources. Визуал определяется AmmoItem.Archetype.VisualIndex: дополнительный поджог или холод не меняет тип и наконечник пули. Обычный патрон без типа использует Plain.

Проверка: `-batchmode -executeMethod BandolierUpgradeValidation.Run` с графическим backend Unity. Проверяются выбор в обоих порядках, поднятие, перестановка, shader spin, отмена/подтверждение, пауза и две стадии; рендеры сохраняются в уникальную папку `.utmp/Artifacts/upgrade-*`. `FiveWaveRunValidation.Run` проверяет весь забег и восемь выборов наград. Для offscreen-презентации в Unity 2022.3 не применять `-nographics`: null renderer в этом режиме может аварийно завершаться.

Скоба `Art/Upgrades/ModuleClip.png` сгенерирована встроенным image_gen. Полный промпт и происхождение — в README папки графики.


## Страницы между волнами

Вкладки «Награды», «Крафт», «Магазин» используют один патронташ и одну анимацию открытия. Вкладки доступны сразу; обязательны только бесплатный патрон и модуль. RunDirector.RewardsComplete показывает, что оба получены, а AwaitingReward остаётся true до ContinueAfterRewards(). Повторный Choose после двух наград отклоняется. Кнопка «Следующая волна» вызывает ContinueAfterRewards; до получения обоих предметов метод возвращает false. Завершение боя и сбор добычи эта задача не меняет.

- CraftingPage создаёт один ShardCraftingService для текущих Economy/Drum. Вид/качество/число осколков берутся из общего RunInventory. Выбор осколка, переключатель «Патрон/Модуль» и гнездо формируют CraftRequest. CanApply управляет доступностью кнопки и причиной отказа; TryApply проводит операцию. UI не списывает ресурс, не генерирует свойства и не вызывает Rebuild/RefreshProfiles: пересчёт выполняет сервис. После успеха текст нового свойства увеличивается и подсвечивается, патрон получает пробегающий блик на unscaled time. Подсказки используют тот же AmmoTooltipContent.
- ShopPage хранит один ShopService на забег, Open(Round) возвращает фиксированный магазин. Список прокручивается, карточки показывают редкость/качество, цену, число осколков и состояние «ПРОДАНО». Патрон выбирается до гнезда или после него; подтверждение вызывает только TryPurchase. Отмена, Esc, смена вкладки и закрытие не завершают покупку. Осколок покупается нажатием на его карточку через тот же сервис. Монеты отображаются сверху, изменения общего инвентаря обновляют страницы без создания нового магазина.
- CartridgeIconCache рендерит для карточек магазина существующий CartridgeVisual с прежними материалами/наконечниками; текстуры кешируются на магазин и освобождаются при новом ассортименте/уничтожении страницы. Новая графика патронов не дублируется.
- Когда осколок/товар не выбран, два нажатия на гнёзда переставляют патроны на любой вкладке, в том числе после получения обеих наград. «Снять выбор» / Esc возвращают этот режим. Модули остаются на местах. Наведение на гнездо показывает прежние две подсказки — патрона и модуля, имплисит остаётся отдельным блоком без поясняющих подписей.

UI подключён к существующему RunUI.ShowReward/HideReward. Интеграционная задача 6 по-прежнему отвечает за регистрацию дропа/монет и ожидание CollectAll до открытия этого экрана и до победы. В UI нет тестовых начислений, нового генератора или второго инвентаря; до регистрации добычи нулевые балансы отображаются корректно.

Проверка: IntermissionUiValidation.Run — настоящее прохождение первой волны и взаимодействия с uGUI-кнопками, реальные сервисы крафта/магазина, затраты/отказы/отмена, неизменный имплисит, отсутствие перезарядки от крафта, стабильность ассортимента, обе обязательные награды, перестановка на трёх вкладках и явное продолжение. Тестовые монеты/осколки начисляются только внутри Editor-проверки. Кадры сохраняются в .utmp/Artifacts/intermission-* при 1280×720 и 1024×768. Существующие BandolierUpgradeValidation/FiveWaveRunValidation/EnemyPressureValidation учитывают явное продолжение.
