# Осколки — задача 2

Самостоятельный сервис, без изменений Enemy, RunUI, RunDirector и общей экономики.
Регистрация и переходы этапов принадлежат задаче 6 согласно Economy/CONTRACTS.md.
Автоматического глобального регистратора нет: он создал бы вторую подписку при интеграции.

## Подключение в задаче 6

Создать **один** экземпляр `Prefabs/Shards/ShardDropService.prefab` на забег после
появления `StaticShooterStage`. Вызвать:

```csharp
var stage = StaticShooterStage.Instance;
shards.Initialize(director.Economy, stage.CollectionTarget,
    groundSurface: stage.GroundSurface);
```

Прямая ссылка настроек уже есть в префабе. Для тестов можно передать другие
`ShardDropSettings` третьим аргументом. Контекст и кошелёк предоставляет вызывающая сторона.
GroundSurface задаёт высоту горизонтальной XZ-плоскости, без raycast и коллайдеров.
Если плоскость не передана, используется контрактная высота позиции смерти.

Перед успешным переходом этапа, наградой или победой, **до Time.timeScale = 0**:

```csharp
yield return shards.CollectAll();
// Теперь можно приостановить игру и открыть магазин/победу.
```

`IShardCollectionService` — дополнительный контракт этой задачи: `PendingCount`,
`IEnumerator CollectAll()`, `Cancel()`. CollectAll ничего не начисляет напрямую,
не телепортирует предметы и не запускает вторую анимацию. Несколько ожидающих
пользуются одним списком. Завершение — прибытие всех предметов либо отмена/конец контекста.
Ожидание включает и новые дропы, появившиеся до опустошения списка.
Пауза честно останавливает и ожидание, и движение: перед ожиданием нужно возобновить
игровое время, если экран уже успел его остановить. Сам сервис не меняет Time.timeScale.

Для поражения/перезапуска достаточно завершения RunEconomyContext: Ended отписывает
сервис, отменяет незавершённые предметы и пробуждает ожидающих. Отключение или выгрузка
сервиса делает то же самое. `Cancel()` отменяет текущие предметы без начисления,
но оставляет подписку для дальнейшего боя. При успешной волне не применять Cancel!
Повторный Initialize тем же активным контекстом не создаёт вторую подписку;
новый контекст отменяет старые предметы и начинает отдельную дедупликацию.
Один экземпляр сервиса должен обслуживать только один активный забег.

## Редактируемые ассеты

- `Resources/Economy/Shards/ShardDrops.asset`: вероятность по типу врага,
  включительный диапазон количества (защитный предел 64), веса трёх видов,
  веса T1/T2/T3 и радиус разброса по XZ. Нулевой шанс = нет дропа,
  нулевой вес исключает вид/качество; все нулевые веса = нет соответствующего дропа.
- `ShardMotion.asset`: левитация (по умолчанию 1 с), высота/частота покачивания,
  продолжительность полёта, высота и боковой изгиб дуги, кривая ускорения и вращение.
  Изменять кривую с концами 0→0, 1→1. Полёт использует квадрат времени для мягкого старта.
- `Prefabs/Shards/ChaosShard.prefab`, `IceShard.prefab`, `LavaShard.prefab`:
  отдельные силуэты, фасетки/материалы и мягкая тень. У T1 три светлых знака и
  масштаб 1,4, у T2 два и 1,2, у T3 один и 1. Вид определяется силуэтом, не только цветом.
  Body, Shadow и три Quality Marks редактируются в инспекторе ShardPickup.
  Скрипт двигает Body и тень; геометрия, материалы и локальные размеры частей остаются авторскими.
- `Art/Shards/`: геометрические ассеты созданы средствами Unity, внешних источников нет.
  Shader Unlit/Color, мягкая тень — собственная радиальная текстура. Collider/Collider2D,
  Rigidbody и Enemy на осколках отсутствуют: они не участвуют в прицеливании/попаданиях.

`Tools > Prototype > Shards > Build missing assets` создаёт только отсутствующие
ассеты и сохраняет последующие ручные изменения. Перегенерация существующих префабов
автоматически не производится.

## Проверка

`ShardDropValidation.Run` в Unity Editor/batchmode. Проверяется настоящее событие
Enemy.Die, повторный урон и повторная доставка DeathId, отсутствие немедленного
начисления, XZ-позиция, пауза, девять одновременных предметов всех видов/качеств,
два ожидающих CollectAll, отмена, завершение контекста, новый забег, удаление предмета
и отключение сервиса. Отдельно проверяются нулевые шансы/веса и диапазоны количества.
Кадр с игровой перспективной камеры: `.utmp/Artifacts/shards.png`.
